5. Findings & Recommendations

CRITICAL
F-001: No DWARF Debug Information Emission
Spec §3.4 requires DWARF debug info (line tables, type descriptors, variable mapping) for step debugging. The MIR preserves spans but the LLVM codegen does not emit !dbg metadata or DIBuilder calls.
Impact: Cannot use GDB/LLDB for source-level debugging.
Recommendation: Add !dbg line metadata to instructions, emit !DICompileUnit, !DISubprogram, !DILocalVariable. Can be done incrementally — start with line tables.
MAJOR
F-002: MLIR/GPU Backend Entirely Deferred
Spec §4 specifies a full MLIR pipeline (Linalg → MemRef → GPU dialect → PTX/AMDGPU/SPIR-V). This is explicitly deferred to Phase 12.
Impact: No GPU compilation. Acceptable for current roadmap — CPU-only path fully functional.
Recommendation: Keep the deferred status. GpuTarget enum and has_gpu_functions() detection provide a clean extension point.
MAJOR
F-003: Tensor Runtime Stubs Not Executable
Spec §5.1 requires tensor operations to produce correct results. The C runtime stubs return input pointers unchanged.
Impact: Tensor ops compile but don't compute. This is by design (Phase 10).
Recommendation: Phase 10 should implement BLAS-backed tensor ops. Current stubs provide correct ABI and clean integration points.
MINOR
F-004: FFI Syntax Not Parsed
Spec §6.3 defines unsafe fn printf(fmt: &String, ...) -> Int32; as FFI import syntax. The parser doesn't handle this.
Recommendation: Add unsafe fn with no body → FFI import detection to the parser. The ABI layer already has CallingConv::C.
MINOR
F-005: Demangle Function is a Placeholder
File: src/codegen/abi.rs:54–59
NameMangler::demangle() returns the input unchanged instead of reversing the mangling scheme.
Recommendation: Implement proper demangling for error messages and debugging.
MINOR
F-006: No Benchmark Suite
Spec T169/T204 require benchmarks for collections and training speed. The benches/ directory exists but no benchmark tests for Phase 5/6 components.
Recommendation: Add criterion benchmarks once Phase 10 provides a runtime.
INFO
F-007: Phase 6 .axon Bodies Return Placeholder Values
All .axon files in stdlib/ use return 0; as placeholder function bodies with detailed algorithmic comments. This is correct for the current phase — the tensor runtime (Phase 10) is required to make these executable. The type signatures, method registrations, and framework structure are complete and match the spec.
INFO
F-008: Exceeds Spec — Additional Types and Methods
Several areas exceed spec requirements: BTreeMap (14 methods), Deque (17 methods), RMSprop optimizer, Adagrad optimizer, EarlyStopping callback, TensorBoard logger, ModelCheckpoint struct. These additions are well-structured and consistent with the existing API design.
