2.6 Minor Gaps

M-01: Bare | token not emitted

The lexer treats a bare | character as an error (E0001) with the hint "did you mean ||?". This means closure parameters like |x| must be parsed differently. The parser handles || for closures, so this is not a functional issue — it's a design decision that prevents | as a bitwise-OR operator but doesn't break any specified feature.

9. Findings & Recommendations

Critical Findings: 0

No critical issues found.

Major Findings: 2

F-01 [MAJOR]: Trait resolution uses flat symbol table lookup instead of proper impl resolution

Spec: §4.3 — "Look up inherent impls → look up trait impls → check bounds"
Actual: Method calls look up TypeName::method in the symbol table. If not found, returns a fresh TypeVar (lenient, no error).
Impact: Calling a nonexistent method on a struct silently succeeds as a type variable. This masks potential bugs in user code.
Location: typeck.rs:906–945
Recommendation: Emit E2011 when no method is found instead of returning a fresh TypeVar. Register impl methods in the symbol table during check_impl.

F-02 [MAJOR]: Borrow checker is AST-walk based — control-flow-dependent violations may be missed

Spec: §6.3 — "Use a simplified MIR-like CFG"
Actual: The borrow checker walks the AST directly rather than building a CFG. BasicBlock and BorrowStmt data structures exist (borrow.rs:96–121) but are unused.
Impact: Violations that depend on control flow paths (e.g., borrow in one branch, move in another) may not be caught.
Location: borrow.rs:1–10 (documented), borrow.rs:155–421 (AST walk)
Recommendation: This is documented as a planned improvement. When MIR is available (Phase 4), migrate to MIR-based borrow checking. Current approach is acceptable for v1.0.

Minor Findings: 3

F-03 [MINOR]: E3006 (dynamic where static required) not implemented

The spec defines E3006 for cases where a dynamic dimension is used where a statically-known dimension is required. This is not implemented. Impact is minimal since dynamic dims are accepted gracefully and deferred to runtime checks.

F-04 [MINOR]: E1003 (ambiguous import) not implemented

Glob imports (use module::*) are not supported, so E1003 cannot be triggered. This is a natural consequence of the current import design and not a regression.

F-05 [MINOR]: &T → &mut T coercion produces &T instead of error E2020

Spec: §4.5 — "&T → &mut T: Never (error E2020)"
Actual: Unification of &T with &mut T demotes to &T instead of producing E2020.
Location: typeck.rs:180–187
Impact: Low — the result is still type-safe (demoting to immutable ref), but doesn't produce the specified error.

Informational Notes: 2

I-01: Excellent error message quality

Error messages consistently include span locations, error codes, and contextual suggestions. The E1001 errors use Levenshtein distance for "did you mean?" suggestions. The E1002 errors include "consider renaming one of them." The E2001 errors suggest explicit type annotations. The W1001 exhaustiveness warning lists missing variants. This exceeds typical compiler error quality.

I-02: Type interner with deduplication is a strong design

The TypeInterner with O(1) equality via TypeId handles, pre-interned common types, and deduplication on intern() is well-designed. The 10 pre-interned constants (Unit, Never, Error, Bool, Int32, Int64, Float32, Float64, String, Char) avoid repeated allocations for the most common types.
